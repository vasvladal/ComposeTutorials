1 Создание нового проекта

  1. Откройте Android Studio и нажмите New Project.
  2. Выберите шаблон Empty Activity и нажмите Next.
  3. Заполните поля проекта:
    • Name: ComposeTutorials
    • Package name: com.smarttoolfactory.tutorial1_1basics
    • Language: Kotlin
    • Minimum SDK: API 24: Android 7.0 (Nougat)
    • Build configuration language: Kotlin DSL
  4. Нажмите Finish и дождитесь индексации.
💡 Совет: Переименование модуля По умолчанию Android Studio создаёт модуль app. Чтобы привести структуру в соответствие с учебным кодом, выполните:
ПКМ на папке app → Refactor → Rename → Tutorial1-1Basics → Do Refactor.

3 Каталог версий (Version Catalog)

Файл gradle/libs.versions.toml — это современный способ централизованного управления зависимостями. Ниже приведён ключевой фрагмент с исправленной версией Accompanist.

⚠️ Критическое исправление Версия 0.37.3 библиотеки accompanist-systemuicontroller не существует на Maven Central. Эта библиотека была помечена как устаревшая, и её последняя доступная версия — 0.36.0. Именно это вызывало ошибку сборки Could not find com.google.accompanist:accompanist-systemuicontroller:0.37.3.

📄 gradle/libs.versions.toml (фрагмент)

TOML 
[versions]
accompanist = "0.37.3"
accompanistSystemUi = "0.36.0"   # 🔥 Исправлено!
androidGradlePlugin = "8.5.2"
androidx-compose-bom = "2024.10.00"
androidx-compose-latest = "1.7.5"
compileSdk = "35"
kotlin = "2.0.21"
minSdk = "24"
targetSdk = "35"

[libraries]
accompanist-systemuicontroller = {
    module = "com.google.accompanist:accompanist-systemuicontroller",
    version.ref = "accompanistSystemUi"  # 🔥 Использует отдельную версию
}
accompanist-drawablepainter = {
    module = "com.google.accompanist:accompanist-drawablepainter",
    version.ref = "accompanist"
}

[plugins]
android-application = { id = "com.android.application", version.ref = "androidGradlePlugin" }
compose = { id = "org.jetbrains.kotlin.plugin.compose", version.ref = "kotlin" }
gradle-versions = { id = "io.github.ben-manes.versions", version.ref = "gradle-versions" }

    alias(libs.plugins.android.application)

        targetSdk = libs.versions.targetSdk.get().toInt()

        versionName = "1.0"
    }

    compileOptions {
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }

    kotlinOptions { jvmTarget = "17" }
    buildFeatures { compose = true }
}

dependencies {
    val composeBom = platform(libs.androidx.compose.bom)
    implementation(composeBom)

    implementation(libs.androidx.core.ktx)
    implementation(libs.androidx.activity.compose)
    implementation(libs.androidx.compose.ui)
    implementation(libs.androidx.compose.foundation)
    implementation(libs.androidx.compose.material3)
    implementation(libs.androidx.compose.ui.tooling.preview)
    debugImplementation(libs.androidx.compose.ui.tooling)

    # Accompanist с исправленной версией
    implementation(libs.accompanist.systemuicontroller)
    implementation(libs.accompanist.drawablepainter)
}

6 Основы Jetpack Compose

Учебный код демонстрирует четыре фундаментальных концепции компоновки:

Компонент Назначение Аналог в XML
Row Горизонтальное расположение детей LinearLayout (horizontal)
Column Вертикальное расположение детей LinearLayout (vertical)
Box Наложение детей (ось Z) FrameLayout
Modifier Свойства: размер, фон, отступы, клик XML-атрибуты
Spacer Пустое пространство + weight Space / weight

🔥 Важнейшее правило: Порядок модификаторов

Порядок модификаторов имеет решающее значение! В Compose модификаторы применяются сверху вниз. Один и тот же набор модификаторов в разном порядке даёт кардинально разный результат.
Сравнение двух подходов 
// 🔴 Вариант A: фон сначала, потом padding
// Результат: фон закрашивает ВЕСЬ блок, padding ВНУТРЕННИЙ
Modifier
    .background(Color.Yellow)
    .padding(15.dp)

// 🔵 Вариант B: padding сначала, потом фон
// Результат: padding создаёт ВНЕШНИЙ отступ (как margin), фон только внутри
Modifier
    .padding(10.dp)
    .background(Color.Cyan)

📐 Weight и распределение пространства

Модификатор weight() работает только внутри Row или Column и распределяет оставшееся свободное пространство пропорционально заданным значениям.

Kotlin 
Row {
    Text("Вес 2", modifier = Modifier.weight(2f))
    Spacer(modifier = Modifier.weight(1f))  // Пустой промежуток
    Text("Вес 3", modifier = Modifier.weight(3f))
    Text("Вес 4", modifier = Modifier.weight(4f))
}
// Сумма весов = 10, ширина делится: 20% | 10% | 30% | 40%

🗂 Box и Z-ось

В Box элементы объявляются последовательно, и каждый следующий рисуется поверх предыдущего:

Kotlin 
Box {
    Text("Первый", Modifier.size(200.dp))  // Внизу (фон)
    Text("Второй", Modifier.size(150.dp))  // Посередине
    Text("Третий", Modifier.size(100.dp))  // Сверху (передний план)
}

7 Исправление типичных ошибок сборки

❌ Ошибка 1: accompanist-systemuicontroller:0.37.3 не найден

Симптом: Could not find com.google.accompanist:accompanist-systemuicontroller:0.37.3

Причина: Библиотека System UI Controller была помечена как deprecated и удалена в более новых версиях Accompanist. Последний релиз — 0.36.0.

Решение: Добавьте отдельную версию в libs.versions.toml:

TOML 
[versions]
accompanist = "0.37.3"
accompanistSystemUi = "0.36.0"  # ← отдельная версия

[libraries]
accompanist-systemuicontroller = {
    module = "com.google.accompanist:accompanist-systemuicontroller",
    version.ref = "accompanistSystemUi"  # ← используем её здесь
}

❌ Ошибка 2: Опечатка в имени переменной

Исходный код содержал опечатку: d rawerState.close() — пробел в имени переменной.

Решение: Замените на корректное имя drawerState.close().

❌ Ошибка 3: Устаревший плагин Gradle Versions

Предупреждение: The com.github.ben-manes.versions plugin id is deprecated

Решение: В libs.versions.toml замените ID плагина:

TOML 
# Было:
# gradle-versions = { id = "com.github.ben-manes.versions", ... }

# Стало:
gradle-versions = { id = "io.github.ben-manes.versions", version.ref = "gradle-versions" }

❌ Ошибка 4: Устаревшие свойства в gradle.properties

AGP 9.0+ изменил значения по умолчанию для многих опций. Явное указание старых значений вызывает предупреждения. Удалите следующие строки или обновите их:

Устаревшая опция Замена
android.builtInKotlin=false android.builtInKotlin=true
android.newDsl=false android.newDsl=true
android.defaults.buildfeatures.resvalues=true android.defaults.buildfeatures.resvalues=false
android.usesSdkInManifest.disallowed=false Удалить

8 Запуск и отладка

  1. В правом верхнем углу Android Studio появится уведомление "Gradle files have changed". Нажмите Sync Now.
  2. Дождитесь сообщения BUILD SUCCESSFUL в нижней панели.
  3. Выполните ./gradlew clean в терминале, чтобы очистить кэш.
  4. Нажмите зелёную кнопку ▶ Run или Shift + F10.
  5. Выберите эмулятор или подключённое устройство.
🎉 Ожидаемый результат Вы увидите прокручиваемый экран с примерами использования Row, Column, Box, Modifier и Spacer. Каждый пример сопровождается текстовым описанием.

🐛 Полезные команды для отладки

Terminal 
# Детальный вывод Gradle
./gradlew assembleDebug --info

# Полная очистка кэша
./gradlew clean build --refresh-dependencies

# Проверка зависимостей конкретного модуля
./gradlew :Tutorial1-1Basics:dependencies

# Отладка устаревших API
./gradlew assembleDebug -Pandroid.debug.obsoleteApi=true
